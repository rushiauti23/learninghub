New to JVM memory? Open Start here first. Each tab steps through a program one line at a time while the panels on the right show what changes in memory. Arrows are references.

Keyboard: ← and → move between steps.

Key terms

The words used on every tab, in plain language. The Start here tab walks through each one with a small program.

JVM (Java Virtual Machine)
The program that runs your Java code. java Shop starts it. It asks the operating system for memory and splits it into the areas below.
Bytecode
What javac turns your .java file into. A list of simple instructions for the JVM, stored in a .class file.
Thread
A worker that carries out instructions one at a time. A program can have many threads working at once.
Main thread
The first thread the JVM creates. Its only job is to run your main method.
Thread stack
Each thread's private notepad. It is a pile of frames, one per method that is currently running. Other threads can't see it.
Stack frame
The scratch space for one method call: its parameters and local variables. Added on top when the method starts, thrown away when it returns.
Local variable
A variable declared inside a method. It lives in that method's frame and disappears when the method returns.
Heap
One big shared storage area for objects. Everything made with new goes here, and every thread can reach it.
Object
A block of heap memory holding the fields described by its class, for example one Customer with its own name.
Field
A variable declared in a class, outside any method. Each object carries its own copy inside its heap block.
Reference
The address of an object on the heap. A variable like Customer cust holds this address, not the object itself. Drawn as an arrow.
Metaspace
Where the JVM keeps class blueprints: each class's fields, methods and bytecode. One entry per class, no matter how many objects you create.
Garbage collector (GC)
A part of the JVM that finds objects no arrow can reach any more and frees their memory, so you never have to.
