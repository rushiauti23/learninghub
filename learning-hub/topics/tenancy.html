Putting this on GitHub Pages

This whole simulator is one file with no build step and no server, so Pages can host it as-is.

git init
git add index.html
git commit -m "Architecture simulator"
git branch -M main
git remote add origin https://github.com/<you>/tenancy.git
git push -u origin main

Then in the repository: Settings → Pages → Source: Deploy from a branch → main / (root) → Save. It goes live at https://<you>.github.io/tenancy/ within a minute or two.

The file must be named index.html and sit at the repository root, otherwise Pages serves a 404 at the root URL.
Deploying from a subfolder or with Actions

If you'd rather keep it in docs/, pick that folder in the same Pages setting. For a workflow-based deploy, add .github/workflows/pages.yml:

name: Deploy
on:
  push: { branches: [main] }
permissions: { pages: write, id-token: write, contents: read }
jobs:
  deploy:
    environment: github-pages
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/upload-pages-artifact@v3
        with: { path: '.' }
      - uses: actions/deploy-pages@v4
Your architecture is kept in localStorage, so a visitor's setup survives a reload without any backend.

How the numbers are produced

Each tier is modelled as a queue with a finite service rate. Capacity is concurrency divided by service time; anything arriving faster than that accumulates as backlog, and backlog is what you feel as latency. Requests waiting longer than the 2-second timeout are abandoned and counted as failures. It's an approximation, not a replica of any real stack — but the shapes it produces (the knee, the cliff, the cascade) are the ones you'll meet in production.
